# Развёртывание TPAM как сайта для других людей

Люди входят на сайт **по номеру телефона и коду из Telegram**, как в обычный Telegram. API ID и API HASH указывает только администратор, один раз на сервере.

> На сервере будут храниться зашифрованные сессии Telegram ваших пользователей. Это ответственность: держите сервер обновлённым, не давайте доступ посторонним, делайте резервные копии вместе с `TPAM_SECRET_KEY`. Опубликуйте условия использования и политику конфиденциальности для своей страны.

## Что нужно

- VPS с Linux (1 vCPU / 1 ГБ RAM хватит на десятки пользователей), Docker и Docker Compose.
- Домен с A-записью на IP сервера, например `tpam.example.com`. HTTPS-сертификат Caddy получит сам.
- API ID и API HASH с https://my.telegram.org → API development tools.

## Установка

```bash
git clone <ваш репозиторий> tpam && cd tpam    # или скопируйте папку проекта
cp .env.example .env
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # → TPAM_SECRET_KEY
nano .env      # TPAM_DOMAIN, TPAM_API_ID, TPAM_API_HASH, TPAM_SECRET_KEY
docker compose up -d --build
docker compose logs -f tpam
```

Откройте `https://ваш-домен` и **сразу войдите сами**: первый вошедший становится администратором (раздел «Пользователи»).

## Как устроено

| Компонент | Назначение |
|---|---|
| `tpam` | Сервер на FastAPI и собранный интерфейс. Данные лежат в томе `tpam-data` (`/data`) |
| `caddy` | HTTPS (Let's Encrypt) и проксирование на `tpam:8765` |
| `/data/server.db` | Пользователи: зашифрованные сессии Telegram и ключи ИИ, браузерные сеансы |
| `/data/users/<id>/` | Данные каждого пользователя: правила, журнал, архив, медиа — отдельно от остальных |
| `/data/guests/` | Демо-гости, удаляются через сутки без активности |

## Безопасность (уже встроено)

- **Только HTTPS:** сервер не запустится на внешнем адресе без `TPAM_PUBLIC_URL=https://…`.
- **Cookie сеанса:** HttpOnly, Secure, SameSite=Lax. Каждый изменяющий запрос требует заголовок `X-TPAM-Request` (защита от CSRF), проверяются Host и Origin, включены HSTS и CSP.
- **Шифрование:** сессии Telegram и ключи ИИ шифруются ключом `TPAM_SECRET_KEY`. Номера телефонов хранятся только в виде хэша и маски.
- **Ограничения на вход:** не больше 3 запросов кода в час на номер, 10 в час с одного IP и 120 в час на весь сервис. На ввод кода и пароля — по 5 попыток. Так никто не сможет израсходовать лимиты вашего API ID.
- **Закрытие регистрации** — переключатель в разделе «Пользователи» или `TPAM_REGISTRATION_OPEN=false`. Уже зарегистрированные пользователи продолжат входить.
- **Изоляция данных:** импорт архива по пути на сервере доступен только администратору, остальные загружают файл `result.json`.

## Обслуживание

```bash
docker compose pull caddy && docker compose up -d --build     # обновление
docker run --rm -v tpam_tpam-data:/data -v "$PWD":/backup alpine tar czf /backup/tpam-data.tgz /data   # бэкап
```

Если `TPAM_SECRET_KEY` потерян, сохранённые сессии расшифровать невозможно: всем пользователям придётся войти заново. Остальные данные (правила, архив) сохранятся.
